# Проверка ввода Windows

[English](README.md) · [Русский](README.ru.md)

Этот каталог задаёт одноразовую границу доказательств M0 для планируемого Windows-адаптера ввода. Рабочая граница должна находиться в `nodavo-platform-windows`: нативные детали Raw Input, hooks и `SendInput` остаются внутри его модулей `ffi`, а остальная часть workspace получает ограниченные семантические события ввода вместо нативных handles или buffers.

Планируемая runtime-проверка должна подтвердить классификацию физических событий клавиатуры и указателя, маркировку и исключение внедрённых событий из повторного захвата, а также освобождение всех отслеживаемых клавиш и кнопок при отключении, блокировке, сне, timeout, восстановлении после сбоя или emergency stop. При отсутствии input capability, недоступной пользовательской сессии или активном secure desktop адаптер должен завершаться безопасным отказом. Диагностика может записывать только ограниченные категории событий и коды ошибок, но не нажатия клавиш и не стабильные идентификаторы устройств.

## Текущая команда и доказательство

Из корня репозитория:

```bash
rustup target add x86_64-pc-windows-msvc
cargo check -p nodavo-platform-windows --target x86_64-pc-windows-msvc
```

Успешная команда является **только доказательством проверки типов** для Windows x64 MSVC. Она не линкует и не запускает Windows executable, поэтому не подтверждает Raw Input, hooks, `SendInput`, подавление внедрённых событий, раскладки клавиатуры, координаты указателя, поведение DPI, смену сессий, аварийное освобождение клавиш или отказ в secure desktop.

Сейчас в этом каталоге нет runtime probe. До закрытия M0 или M2 всё ещё нужны проверки на реальном Windows-оборудовании x64 и ARM64, включая lifecycle и стресс-тест высокочастотного ввода.
