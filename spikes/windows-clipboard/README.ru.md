# Проверка буфера Windows

[English](README.md) · [Русский](README.ru.md)

Этот каталог задаёт одноразовую границу доказательств M0 для планируемого Windows-адаптера буфера обмена. Рабочая граница должна находиться в `nodavo-platform-windows`: вызовы Win32 Clipboard и OLE, владение, нативное выделение памяти и доступ к buffers остаются внутри его модулей `ffi`. Безопасная сторона должна получать собственные ограниченные представления вместо нативных handles или pointers.

Планируемая runtime-проверка должна подтвердить наблюдение за ревизиями буфера и ограниченное обнаружение форматов текста, HTML и изображений без записи содержимого буфера в логи. Пути чтения и записи должны обрабатывать занятость буфера, отклонять повреждённые или слишком большие представления до копирования, корректно освобождать нативное владение, требовать явную clipboard capability и предотвращать циклы синхронизации. Файловый буфер и drag/drop остаются отдельной работой и не должны подразумеваться этим spike.

## Текущая команда и доказательство

Из корня репозитория:

```bash
rustup target add x86_64-pc-windows-msvc
cargo check -p nodavo-platform-windows --target x86_64-pc-windows-msvc
```

Успешная команда является **только доказательством проверки типов** для Windows x64 MSVC. Она не линкует и не запускает Windows executable, поэтому не подтверждает поведение Win32 Clipboard или OLE, преобразование форматов, владение и блокировку, отклонение повреждённых данных, лимиты размера, предотвращение циклов, поведение сессии или отказ в secure desktop.

Сейчас в этом каталоге нет runtime probe. До закрытия M0 всё ещё нужны проверки на реальном Windows-оборудовании x64 и ARM64, включая clipboard churn и lifecycle stress.
