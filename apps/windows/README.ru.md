# Nodavo для Windows

[English](README.md) · [Русский](README.ru.md)

В этом каталоге находится первая нативная оболочка Nodavo на WinUI 3. В ней есть двуязычные разделы обзора, устройств, расположения, передач и настроек. Обзор реализует ограниченные запросы статуса и аварийного отключения. Экран устройств реализует ожидающее/ручное сопряжение, явный выбор отдельных разрешений, сравнение шестизначного кода, взаимное подтверждение, отмену и честные состояния pre-alpha; незавершённые экраны показывают недоступность, а не имитируют работающую функцию.

## Поддерживаемые цели исходного проекта

- Windows 10 22H2 и Windows 11.
- Конфигурации x64 и ARM64.
- Упакованные тестовые сборки MSIX и неупакованные тестовые сборки.
- Работа только в сеансе текущего пользователя. Манифест запрашивает `asInvoker`; экран входа, защищённый рабочий стол UAC, Session 0 и привилегированное управление без присутствия пользователя не поддерживаются.

## Сборка на Windows

Установите Visual Studio 2022 версии 17.10 или новее с workload для разработки Windows-приложений, .NET 8 SDK, Windows 10/11 SDK 10.0.26100 и инструменты MSIX. Затем выполните из корня репозитория:

```powershell
dotnet restore apps/windows/Nodavo.Windows.sln -p:Platform=x64
dotnet build apps/windows/Nodavo.Windows.sln -c Release -p:Platform=x64
```

Для неупакованной тестовой сборки:

```powershell
dotnet build apps/windows/Nodavo.Windows.sln -c Release -p:Platform=x64 -p:NodavoPackageMode=Unpackaged
```

Используйте `ARM64` и `win-arm64` на настоящем сборочном компьютере Windows ARM64. Добавленные publish-профили предназначены для разработки, а не для подписанного релиза.

Для запуска неупакованной сборки требуется соответствующий Windows App Runtime. Для публичного устанавливаемого MSIX нужны настоящая издательская идентификация и сертификат Authenticode; в репозитории их нет.

## Контракт локального IPC

Интерфейс подключается к `\\.\pipe\nodavo-agent-{SID-текущего-пользователя}` с опцией .NET, разрешающей именованный канал только текущему пользователю. Каждое сообщение состоит из четырёхбайтовой беззнаковой длины в big-endian и UTF-8 JSON; жёсткий предел — 64 КиБ. Оболочка отправляет `get_status`, `emergency_stop`, `begin_pairing` и `confirm_pairing`; у долгих запросов сопряжения есть ограниченный тайм-аут и отмена из интерфейса. Все разрешения по умолчанию выключены, а явный выбор подписывается в доверии сопряжения. Оболочка не записывает в журнал тела ответов, трафик устройств, ввод, буфер, имена файлов, коды сопряжения, ключи и постоянные сетевые идентификаторы.

## Текущие ограничения

На текущем macOS-компьютере исходники не компилировались, не линковались и не запускались под Windows. Здесь можно проверить XML, соответствие локализаций и инварианты исходного кода, но подтверждение сборки и runtime требует Windows CI и настоящих компьютеров Windows x64/ARM64.

В исходниках Rust уже есть сервер named pipe с проверкой того же пользователя/сеанса и защищённое DPAPI-хранилище идентификаторов/доверия, а в этой оболочке — соответствующий сценарий сопряжения. На macOS они проходят cross-compile или проверки исходников/XML, но ещё не были слинкованы и запущены вместе на Windows, поэтому успешный runtime не заявляется. Интерфейс разрешений/отзыва доверенных устройств, редактирование расположения, маршрутизация ввода, буфер, передачи, трей, автозапуск, диагностика, обновления, установщики и подпись ещё разрабатываются. В `Package.appxmanifest` указаны тестовые издатель и версия пакета; такую сборку нельзя распространять как стабильный релиз.

Интерфейс и IPC-код — оригинальная clean-room разработка на основе собственной архитектуры и контракта локального IPC Nodavo; исходники и ресурсы сторонних KVM-продуктов не использовались.
