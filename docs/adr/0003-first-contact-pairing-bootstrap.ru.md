# ADR-0003: Bootstrap первого контакта при сопряжении

[English](0003-first-contact-pairing-bootstrap.md) · [Русский](0003-first-contact-pairing-bootstrap.ru.md)

- Статус: принято для pre-alpha реализации M1
- Дата: 2026-08-10

## Контекст

Nodavo не доверяет mDNS или введённому вручную адресу. Первое QUIC-соединение должно быть зашифровано, но два ещё не сопряжённых устройства пока не знают, какой самоподписанный временный TLS-сертификат закрепить. Приём любого сертификата через permissive TLS verifier создал бы скрытый trust-on-first-use и усложнил проверку транспортной границы.

## Решение

Явная попытка сопряжения открывает краткоживущий ограниченный TCP preflight по тому же обнаруженному или введённому адресу. Preflight обменивается только:

- фиксированным magic value и версией протокола;
- свежим временным сертификатом в ограниченном DER-представлении;
- его ограниченным TLS server name.

Preflight намеренно неаутентифицирован, а его значения считаются контролируемыми атакующим. Каждое устройство закрепляет точный полученный сертификат до создания QUIC-соединения сопряжения с TLS 1.3. Через TCP не принимаются ввод, буфер, файлы, секрет постоянного идентификатора, разрешение capability или запись доверия.

После установки QUIC pairing reducer получает шестизначный SAS из role-ordered transcript, включающего TLS exporter, версию протокола, оба nonce, оба постоянных Ed25519-идентификатора, хеши обоих постоянных TLS-сертификатов и предложенные grants. Оба локальных интерфейса должны показать и подтвердить одинаковый SAS. Затем оба постоянных идентификатора подписывают принятие до фиксации доверия любой стороной.

Агент допускает только одну активную транзакцию сопряжения, проверяет лимиты bootstrap и pairing frames до выделения памяти, применяет deadlines и закрывает соединение при неверном состоянии. Обычные логи не содержат адреса, сертификаты, идентификаторы, SAS или pairing payloads.

## Последствия для безопасности

- Сетевой атакующий может заменить или ретранслировать preflight metadata, но не может незаметно создать постоянное доверие. Обычный MITM получает разные TLS exporters/transcripts и поэтому разные SAS на двух настоящих устройствах.
- Шестизначный SAS предназначен для сравнения человеком, а не является паролем. Попытки должны быть ограничены по частоте и времени, а несовпадающие значения нельзя подтверждать.
- Plaintext не является режимом совместимости приложения: preflight публикует только недоверенные metadata первого контакта, которые сами по себе не дают capability.
- Постоянное переподключение не использует preflight повторно. Оно требует взаимно закреплённых сертификатов из аутентифицированного защищённого хранилища.

## Отклонённые альтернативы

- Permissive проверка сертификата или silent TOFU: противоречат модели угроз.
- Публикация постоянного ключа или fingerprint через mDNS как идентификатора: discovery не является доверием.
- Облачный rendezvous/account service: противоречит local-first объёму 1.0.
- Поставка приватного проектного CA: создаёт новый ценный секрет и проблему распространения.

## Примечание о хранении

Локальный pre-alpha smoke path использует явно предназначенный только для разработки ограниченный private file fallback. До релизной квалификации stable-сборки должны заменить его на Keychain в macOS и DPAPI/CNG-хранилище в Windows.
