# Протокол Nodavo между устройствами

[English](protocol.md) · [Русский](protocol.ru.md)

## Статус

Этот документ описывает текущую pre-alpha основу wire-протокола из `nodavo-protocol` и контракт каналов из `nodavo-transport`. Это не стабильная спецификация 1.0. Теги и структуры могут меняться до фиксации release candidate; несовместимые изменения должны одновременно обновлять версию протокола и этот документ.

Сопряжение и установление доверия определены в [модели безопасности](security-model.ru.md). Обнаружение предоставляет только сетевой адрес и никогда не принимается за идентификатор устройства.

## Транспорт и разделение каналов

Устройства используют QUIC поверх TLS 1.3. Для разных типов данных действуют независимые области backpressure, поэтому заменяемое движение указателя не может задерживать клавиши, управление, буфер или файлы.

| Данные | Путь QUIC | Правило доставки | Жёсткий лимит приложения |
| --- | --- | --- | ---: |
| Согласование, разрешения, сессии, фокус, топология дисплеев, liveness, ошибки | Двунаправленный control stream | Упорядоченно и надёжно | 64 KiB на сообщение протокола |
| Клавиши, кнопки указателя, надёжный pointer entry, принудительное отпускание | Reliable input stream | Упорядоченно и надёжно | 1 KiB на сообщение протокола |
| Relative pointer delta и частая прокрутка | QUIC datagrams | С sequence; применяется актуальное допустимое движение | 1 200 байт |
| Запасной путь указателя | Короткоживущий reliable stream | Если datagrams недоступны; принимаются только заменяемые события указателя | 1 KiB на сообщение протокола; 1 MiB на транспортный frame |
| Представления буфера | Ограниченные streams на каждую ревизию | Надёжно, с адресацией по содержимому | Блок 256 KiB; отдельные общие лимиты |
| Манифест и содержимое файлов | Манифест и однонаправленные file streams | Надёжно, через staging и хеширование | Манифест 1 MiB; 10 000 записей; всего 10 GiB |

Транспорт отклоняет пустые datagrams, frames больше согласованного или жёсткого лимита, более 64 открытых каналов приложения, неверное владение каналом и операции, превысившие deadline.

## Канонический envelope

Управляющие и семантические сообщения ввода используют каноническую CBOR map с числовыми ключами:

| Ключ | Поле | Значение |
| ---: | --- | --- |
| `0` | `version` | Major- и minor-версия протокола |
| `1` | `tag` | Числовой тип сообщения |
| `2` | `critical` | Должен ли получатель отклонить неизвестное сообщение |
| `3` | `payload` | CBOR bytes тела указанного типа |

Декодеры проверяют лимит соответствующего канала до декодирования, требуют идентичного повторного кодирования envelope и тела, отклоняют неизвестные critical tags и сохраняют ограниченные неизвестные non-critical сообщения как непрозрачные данные. Версия `0.x` недопустима. Текущий codec сообщений между устройствами принимает только pre-alpha версию `1.3`; minor-версия изменена для reliable pointer entry и relative motion и не изменяет отдельную версию pairing preflight. Это также не означает, что сам продукт выпущен как 1.0.

## Текущие теги

| Диапазон/тег | Значение | Канал |
| --- | --- | --- |
| `0` | Hello и согласование версии/возможностей | Control |
| `1`–`2` | Выдача и отзыв разрешений | Control |
| `3`–`4` | Открытие и закрытие сессии | Control |
| `5`–`7` | Запрос, выдача и освобождение focus lease | Control |
| `8`–`9` | Ping и pong | Control |
| `10` | Аварийное отключение | Control |
| `11` | Ограниченная ошибка протокола | Control |
| `12`–`13` | Versioned snapshot топологии дисплеев и acknowledgement | Control |
| `14` | Acknowledgement надёжного pointer entry | Control |
| `0x1000`–`0x1001` | Клавиши и кнопки указателя | Reliable input |
| `0x1002`–`0x1003` | Движение указателя и прокрутка | Datagram или pointer fallback |
| `0x1004` | Принудительное отпускание всего нажатого | Reliable input |
| `0x1005` | Ограниченный relative pointer delta | Datagram или pointer fallback |
| `0x1006` | Начальный absolute pointer entry | Reliable input |
| `0x2000`–`0x2004` | Offer, clear, request, chunk и abort буфера | Clipboard |
| `0x3000`–`0x3003` | File manifest, resume, cancel и complete | File manifest |
| `0x4000` | Блок содержимого файла | File data |

Сообщения буфера и передачи файлов теперь имеют pre-alpha канонические codecs и зарезервированные диапазоны. Они применяют отдельные лимиты типов буфера, блоки 256 KiB, границу file manifest 1 MiB/10 000 записей/10 GiB, нормализованные безопасные relative paths, точные 32-byte hashes, ненулевые transfer identifiers, разделение каналов и redacted debug без содержимого и путей. Они не являются доступной функцией продукта, пока agent и оба platform adapters не завершат сквозной capability-checked session path.

## Идентификатор, актуальность и разрешения

Каждое событие ввода содержит:

- случайный идентификатор сессии;
- идентификатор аутентифицированного устройства-источника;
- монотонно проверяемый sequence в отдельном control, reliable-input или replaceable-input lane;
- текущую эпоху разрешений;
- ровно разрешение удалённого ввода;
- ненулевой идентификатор focus lease, разрешающего событие, включая принудительный release-all.

Focus lease имеет ненулевой идентификатор и ограниченный срок действия. Запрос сообщает, требуется ли reliable pointer entry. Когда он требуется, controller не включает native suppression и не отправляет relative motion, пока receiver не установит надёжную entry position и не вернёт привязанный к сессии acknowledgement. Получатель проверяет всё событие, активный lease, grant нужного направления, entry gate и watermark соответствующего lane до сохранения нового sequence. Он отклоняет устаревшие grants и sequence, неверный источник, другую сессию, некорректные нулевые идентификаторы или событие без нужного grant. Обычное аутентифицированное освобождение фокуса очищает нажатое состояние и возвращает локальное владение, сохраняя сессию готовой. Аварийная остановка, блокировка, сон, потеря связи, инвалидирование grant и истечение lease синхронно очищают lease, entry gate и модель нажатых клавиш и закрывают сессию до возобновления маршрутизации ввода.

Топология дисплеев — critical ограниченное control-сообщение со своей версией схемы, ненулевой ревизией, максимум 32 дисплеями и ограниченными значениями pixel geometry, scale и origin. Она использует общий аутентифицированный control replay lane. Отправитель назначает непрозрачные идентификаторы дисплеев только для текущей сессии; platform-native display IDs никогда не передаются по соединению. Snapshot становится доступным для маршрутизации только после авторизации reducer'ом и acknowledgement точной ревизии. Обычный focus reducer отклоняет запрос фокуса, пока топология нужного направления не установлена или не подтверждена.

Разрешения отдельно представлены для удалённого ввода, чтения буфера, записи в буфер и передачи файлов. Локальный grant, разрешающий ввод от peer, отслеживается независимо от peer grant, разрешающего исходящий локальный ввод. Clipboard request требует ровно read capability; offer, clear и content chunk требуют ровно write capability. File manifest, resume/cancel/complete control и data chunk требуют ровно file transfer. Само транспортное соединение никогда не выдаёт разрешение.

## Семантика ввода

Начальный pointer entry содержит ненулевой session-scoped идентификатор дисплея и нормализованные fixed-point координаты; принимающий agent разрешает token через локальную session map до injection. После acknowledgement физическое движение представлено ненулевым ограниченным signed `PointerDelta` без display identity. macOS получает его из CGEvent deltas и injects относительно текущего cursor location; Windows использует Raw Input deltas и relative `SendInput`. Scroll явно использует `Lines` или `Precise`; zero/zero некорректен. Delta и scroll сохраняют metadata через datagrams или pointer fallback. Relative deltas coalesce только когда их точная сумма остаётся в границах; overflow остаётся отдельным queued motion и не обрезается молча. Reliable-input codec принимает pointer entry, но отклоняет replaceable events; fallback отклоняет keys, buttons, entry и release-all. Инъецированные события получают platform tag и не захватываются повторно.

Edge adjacency является локальной конфигурацией, а не authority из peer topology. Пустая adjacency отключает автоматический edge switching. Явно настроенные routes используют ограниченные logical-DPI transforms, dwell/debounce, hysteresis и cooldown, но всё равно запрашивают обычный аутентифицированный focus lease. При local focus absolute positions используются только для edge detection; после reliable entry acknowledgement маршрутизация использует физические relative deltas, поэтому движение может продолжаться за локальной OS edge. Есть focused tests и cross-target compile, но до утверждения release-proven поведения 1.0 остаётся проверка на реальном macOS/Windows hardware.

Текстовый ввод для раскладок, dead keys, AltGr и IME fallback остаётся задачей версии 1.0 и будет описан до фиксации протокола.

## Правила совместимости

- До открытия сессии устройства должны согласовать общую major/minor версию.
- Изменение смысла существующего поля или тега требует несовместимого изменения версии.
- Дополнительное необязательное поведение использует новый non-critical tag или явно optional поле с детерминированным значением по умолчанию.
- Неизвестные capability bits, некорректное каноническое кодирование, нарушение лимитов и неизвестные critical tags закрывают соединение безопасно.
- Plaintext mode, ввод через early data, доверие из discovery и silent trust-on-first-use запрещены.

## Логи и диагностика

Обычные логи могут содержать ограниченные категории ошибок и временное состояние, но никогда не содержат ввод, содержимое буфера или файлов, приватные имена файлов, pairing codes, приватные ключи, стабильные идентификаторы устройств или сети.
