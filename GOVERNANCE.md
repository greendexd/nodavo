# Governance

Nodavo begins as a maintainer-led open-source project. The initial maintainer is [@greendexd](https://github.com/greendexd).

## Decision process

- Routine fixes are decided through pull-request review.
- Public APIs, protocol changes, trust boundaries, licensing, telemetry, and supported-platform changes require an issue or RFC before implementation.
- Durable architecture decisions are recorded as ADRs under `docs/adr/`.
- Security may justify a temporary private fix, followed by public documentation after coordinated release.

## Roles

- **Contributor:** submits accepted documentation, tests, code, design, or research.
- **Reviewer:** demonstrates sustained expertise in a project area and reviews changes there.
- **Maintainer:** can merge, release, manage security reports, and appoint reviewers or maintainers.

Appointments are based on consistent, constructive work and sound judgment—not commit count alone. Maintainers may step down at any time and should arrange transfer of release and security responsibilities.

## Project assets

Release keys, package namespaces, domains, and repository administration must be held for the benefit of the project. Before stable 1.0, the project will document backup maintainers and recovery procedures for critical assets.
